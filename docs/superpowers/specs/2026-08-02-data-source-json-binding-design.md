# 数据源管理与组件 JSON 绑定设计

## 目标

数据源管理只负责各种协议、请求和连接的生命周期管理；组件通信负责决定具体使用哪一个数据源中的哪一段数据。系统不再要求用户预先维护全局点位目录。

## 职责边界

### 数据源管理

- 管理 HTTP、MQTT、MySQL、SQL Server、Redis、Socket、WebSocket 等数据源。
- 支持新增、编辑、删除、启停、保存、测试连接和测试数据。
- 展示连接状态、最近测试时间、耗时和错误摘要。
- 测试成功后缓存一份最新样例快照，供通信面板选择字段。
- 不展示或维护数据点位、JSON 解析树、绑定关系和组件使用情况。

### 组件通信

- 按照属性面板相同的分组和顺序展示可绑定属性。
- 每个属性独立配置数据源、JSONPath、期望类型、静态兜底值和可选转换。
- 用户先选择数据源，再从最新样例 JSON 中点选字段或手动填写 JSONPath。
- 保存前展示解析结果和类型兼容状态。
- 动态数据正常时覆盖静态属性；数据异常、超时或路径失效时恢复静态值。
- 信号灯按属性中的 `signalColorCount=1..8` 展示 `signalColors.0..7` 对应颜色项，并提供独立的 `signalOpacity`；减少灯数后保留已经绑定的高位项，直到用户解除关系。

## 数据源界面

沿用当前系统现有样式：白色工作区、细边框、小圆角和绿色强调色。

- 左侧固定连接清单，包含新建连接、名称/地址/协议别名/状态搜索，以及状态和协议组合筛选。
- 普通来源归入“连接配置”，内置颜色/数值样例归入“接口 Demo”；Demo 默认折叠，输入搜索词时匹配组自动展开。
- 每行显示固定协议配色和完整状态文字，不能只用颜色表达协议或连接状态。
- 筛选隐藏当前编辑项时保留右侧连接和未保存草稿，并提供清除筛选、展开所属组的定位入口。
- 保存、保存并测试、删除和连接详情加载固定使用操作开始时的连接 ID；等待期间锁定冲突操作并禁用可编辑配置区，切换、新建和关闭前确认未保存草稿。
- 连接变更成功与后续列表刷新失败分别反馈；全局提示在加载、空态和详情状态下始终可见，详情加载失败时保留原选择和原详情。
- 每条连接右侧并排显示编辑和删除按钮；删除需要二次确认。
- 右侧顶部显示名称、协议和状态，只保留测试连接与保存操作。
- 主体显示基础信息、启用开关、协议配置和折叠的高级配置。
- 底部只显示紧凑的最近测试结果，不常驻展示响应 JSON。
- 删除数据点位页签、点位数量、点位搜索和解析结果表格。
- 桌面保持左右布局；视口不超过 `680px` 时改为上方连接清单、下方连接配置的上下布局。

## 通信界面

属性列表仍使用现有右侧面板宽度。点击属性的“绑定”后，在同一面板进入单列配置页：

1. 选择数据源。
2. 读取该数据源的最新样例快照。
3. 点选 JSON 节点自动生成 JSONPath，或手动编辑路径。
4. 查看解析值、数据类型和兼容状态。
5. 点击“应用绑定”。

JSON 树按需展开。第一版只开放 JSONPath 和受控转换，不允许执行用户自定义 JavaScript。数组节点可以整体选择；文本、颜色、开关等属性只接受兼容的标量，表格和图表可以接受数组或对象。

## 统一快照

各种协议在运行层转换为 JSON 兼容快照：

```ts
interface DataSnapshot {
  sourceId: string
  revision: number
  timestamp: string
  quality: 'good' | 'stale' | 'bad' | 'error' | 'offline' | 'testing' | 'unknown'
  data: unknown
  meta?: Record<string, unknown>
}
```

- HTTP JSON 直接作为 `data`；文本、数字和布尔值保留原类型。
- MQTT 消息能解析为 JSON 时保存对象，否则保存字符串，同时在 `meta` 中保存 Topic。
- SQL 查询统一为 `{ columns, rows, total, page, pageSize }`，必须分页和限制结果量。
- Redis 根据 String、Hash、List、Set 等类型转换为标量、对象或数组。
- Socket 二进制先在数据源侧完成分帧和解码，再生成快照。

本地目录为 MQTT、HTTP、MySQL、SQL Server、Redis、Socket 和 WebSocket 各提供颜色、数值两个内置 Demo。每条样例都用根 `value` 保持 `$.value` 的快捷绑定兼容，同时提供 `protocol`、类型字段 `kind`、`status` 等公共信息；颜色样例增加 `palette/states`，数值样例增加 `series/metrics/unit`，两类都包含标准 `table`。这些字段仅用于本地测试，不改变生产适配器或组件请求模型。

## 表格绑定数据格式

标准表格数据集为：

```json
{
  "columns": [
    { "key": "device", "title": "设备" },
    { "key": "value", "title": "数值" }
  ],
  "rows": [
    { "device": "风机 A", "value": 1480 },
    { "device": "风机 B", "value": 1520 }
  ]
}
```

JSONPath 推荐指向完整数据集，例如 Demo 的 `$.table`，从而保留 `columns[].title`。`$.table.rows` 也可以绑定，但列名由行内容推断。`columns` 可省略：对象行按键推断列，数组行按最大宽度推断，标量行生成单列“值”。单元格应优先使用 string、number、boolean 或 null 等标量。运行时最多物化 50 行、12 列；复杂值格式化最多读取 4 层、12 个对象键、12 个数组项和 48 个总条目，最终显示不超过 256 个字符。更大结果由数据源分页、筛选或聚合后再进入快照。

## 绑定模型

```ts
interface PropertyBinding {
  target: string
  sourceId: string
  jsonPath: string
  adapter?: 'first' | 'join' | 'template'
  enabled: boolean
}
```

组件 ID 由绑定所在节点确定，期望类型和静态兜底值从 `componentBindingSchema` 与节点属性读取，不在每条绑定中重复保存。界面上每个属性独立保存绑定。运行时对相同的 `sourceId + jsonPath` 自动复用解析结果，不增加用户可见的点位或模板概念。旧图纸中的 `{ target, pointId }` 继续兼容读取和渲染，但新界面只创建 JSONPath 绑定。

信号灯颜色关系使用固定目标 `signalColors.0` 至 `signalColors.7`，灯光不透明度使用 `signalOpacity`。`signalColorCount` 是属性配置而不是绑定目标，只决定未绑定颜色项的可见范围；已绑定高位目标不随数量减少而被静默删除。动态颜色和不透明度只覆盖运行时视觉副本，来源异常时逐项回退静态属性，不写回图纸或撤销历史；旧版单个 `signalColor` 继续作为第一灯位回退值。

## 性能约束

- 连接清单每次重算只允许一次来源遍历，并在同一模型中生成全局统计、协议计数、筛选结果和两个分组；筛选结果保留来源引用，不复制点位或响应正文。
- Demo 折叠只是减少默认可见项，不等同于虚拟列表、窗口化或分页；展开组的渲染成本仍与匹配连接数量相关，文档和验收不得作尚未实现的常数级 DOM 承诺。
- 一个数据源只请求或订阅一次，所有组件共享最新快照。
- 建立 `sourceId -> bindings` 反向索引，更新时只计算受影响的属性。
- JSONPath 在保存时预编译，相同路径每个快照版本只解析一次。
- 信号灯每个节点最多处理 8 个颜色目标；物化时最多复制一次 8 项调色板，同源多路径继续复用一条源快照流。
- 高频消息只保留最新值，不建立无限消费队列。
- 同一动画帧内的属性变化合并后统一提交画布。
- 文本、颜色和开关默认按 50 至 200ms 节流；动画相关数据按帧合并。
- 大型 JSON 应由采集适配器在 Web Worker 中解析；JSON 树按需展开并设置单层、总可见数和深度预算。
- 表格与图表只接收分页或增量结果，SQL 禁止一次返回完整大表；单个表格快照遵守 50 行、12 列及复杂单元格格式化预算。
- 性能监控记录请求耗时、解析耗时、待更新绑定数和丢弃的中间消息数。

## 异常处理

- 数据源无样例时，通信面板提示先执行连接测试。
- JSONPath 无结果、类型不兼容或数据超时时，绑定行显示异常并使用静态兜底值。
- 数据源结构变化不自动改写路径，避免错误绑定其他字段。
- 删除仍被组件引用的数据源时，先显示引用数量并要求二次确认；删除后相关绑定进入失效状态。
- 连接凭据后续由后台安全保存，图纸 JSON 只保存数据源编号和绑定规则。

## 验证范围

- 数据源新增、编辑、删除、启停、保存和测试。
- 连接名称、地址、协议全称/简称和状态搜索，状态与协议组合筛选，全局计数不受筛选影响，以及普通连接/接口 Demo 分组。
- Demo 默认折叠、搜索展开、当前编辑项被隐藏后的草稿保留和定位，以及 `680px` 以下上下布局。
- 异步操作目标固定、冲突操作及配置表单锁定、未保存草稿确认、全局提示可见、刷新失败分层提示、详情加载失败回退，以及弹窗焦点循环和极短视口纵向访问。
- 七种协议的原示例快照，以及每协议颜色/数值两个内置 Demo 的生成和一次性增量迁移。
- JSON 树点选、手动 JSONPath、类型检查和静态值回退。
- 14 条 Demo 的 `$.value` 兼容性、颜色/数值丰富字段、`$.table` 自定义表头与行数据，以及 `$.table.rows` 自动列推断。
- 信号灯 `signalColorCount=1..8` 的通信项对应关系、同源多 JSONPath 独立灯位、`signalOpacity` 上下界、高位绑定可解除、旧单色回退、保存重开和运行时不修改图纸。
- 多组件共享同一数据源和同一路径时只请求、解析一次。
- 高频更新、组件数量较多、大 JSON 和表格分页场景下的帧率与响应时间。

## 实施状态

设计已经进入正式 `tc2d` 项目：数据源生命周期管理、内存快照、安全 JSONPath、通信绑定、静态回退、旧图兼容、内置 Demo、表格数据集适配和按帧性能链路均已实现。独立 UI 原型只保留为前期设计记录，不再作为运行入口。
