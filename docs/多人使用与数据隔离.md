# 多人使用与数据隔离

## 当前实现范围

当前版本支持多人各自使用独立工作空间，不支持多人实时共同编辑同一张图纸。

浏览器恢复缓存的隔离规则：

- 工作空间由 URL 参数 `workspace` 或“我的”页的工作空间名称确定。
- 图纸恢复缓存键为 `tc2d-project:<encodedWorkspaceId>`，不同工作空间不会写入同一个 localStorage 槽位。
- 旧的 `tc2d-project` 仅迁移到“默认工作区”一次，迁移成功后删除旧键。
- 切换工作空间会先更新当前恢复缓存，再加载目标工作空间；目标不存在时创建空白图纸。
- 切换图纸时清空撤销重做、剪贴板、选择、实时值、通信连接和预览状态，避免跨图纸恢复或显示旧数据。
- 图纸包含 `projectId`、`revision`、`createdAt` 和 `updatedAt`。同一图纸的旧修订不能静默覆盖其他标签页已经保存的新修订。
- 新节点、连线和线稿使用 UUID。打开图纸时会检查文件大小、对象数量、路径点数量、重复 ID 和无效连线端点。

顶部“保存”的正式结果是图纸文件；`localStorage` 只负责页面刷新或意外关闭后的会话恢复。项目根目录 `图纸库/` 是本地文件服务的默认共享目录，本身不按浏览器工作空间或账号隔离。不同用户使用相同文件名时，不能依赖恢复缓存防止磁盘文件冲突。打开对话框的删除使用 ETag 阻止误删已更新版本，但当前本地服务没有账号权限边界，成功删除仍会对共享该目录的所有工作空间生效。

这些规则用于避免同一浏览器中的恢复状态串用，不构成账号身份认证或安全权限边界。浏览器用户可以修改 URL、localStorage 和打开的文件，因此不能信任客户端提交的归属字段。

## 当前服务适配层

前端已经把后台依赖收敛到 `src/services/`，但默认装配仍是本地开发适配器：

- `drawingRepository` 使用当前 Vite 同源图纸 API，并保留 ETag 条件保存和删除。
- `timeService` 请求同源服务器时间，失败后返回带 `source: 'local'` 的本机时间。
- `runtimeGateway` 当前只生成模拟数据，不建立真实 WebSocket、MQTT 或 HTTP 连接。
- `operationGateway` 当前为空实现，不在浏览器或网络保存操作记录。

`backendRequestContext()` 提供的 `workspaceId/projectId/revision` 仅用于未来仓储路由和乐观锁，当前本地仓储不会把它拼入 URL。设置 `VITE_API_BASE_URL` 可以把 HTTP 请求切到独立后台基地址，但不会自动增加登录、权限、数据库或真实实时通信能力。

浏览器文件选择器是用户对本机文件的显式授权，和服务器图纸仓储是两个权限域。“打开其他位置/另存为”不能因接入后台而自动变成服务器文件操作。

## 生产后端边界

接入账号系统后，每次图纸请求和实时数据消息至少包含以下服务端上下文：

```text
tenantId / userId / workspaceId / projectId / revision
```

实施要求：

1. `tenantId` 和 `userId` 必须从服务端验证后的会话或令牌取得，不能采用请求体中的同名字段。
2. 数据库查询和唯一约束至少使用 `(tenantId, workspaceId, projectId)`，所有列表、读取、更新、删除和文件下载都执行相同权限过滤。
3. 保存使用 `revision` 乐观锁。更新条件包含当前修订号，冲突返回 `409 Conflict`，客户端选择重新加载或另存副本。
4. WebSocket 或 MQTT 订阅在服务端绑定租户和工作空间，消息路由不能只依赖组件 `dataKey`。
5. 打开文件中的 `projectId` 和所有者信息仅作为文档元数据；实际归属由当前已认证工作空间重新确定。
6. 服务端审计保存操作者、工作空间、图纸、修订号和时间，不记录不必要的图纸正文或敏感实时值。
7. 默认图纸目录必须按租户、用户或工作空间建立服务端命名空间；所有列表、打开和保存请求都在认证后的根目录内解析规范化文件名，不能接受客户端任意绝对路径。

推荐保存接口语义：

```http
PUT /api/workspaces/{workspaceId}/projects/{projectId}
If-Match: "<revision>"
```

服务端成功保存后返回新的 `revision`。同一图纸需要实时共同编辑时，应另行设计对象级操作日志、锁或 CRDT，不能直接复用最后写入者覆盖模型。

生产数据通道必须分开设计：

| 通道 | 内容 | 一致性与频率 |
| --- | --- | --- |
| 图纸快照 | 节点、连线、组件模板、画布设置 | 用户保存时写入，使用 revision/ETag 乐观锁 |
| 操作事件 | 可选的审计事件或协作命令 | 批量、限频、可重放协议；不能信任客户端操作者身份 |
| 实时数据 | `{ key, value }[]` 设备值 | 高频推送、逐帧合并，不进入图纸或撤销历史 |

服务端审计应在已认证请求处理完成后生成权威记录。前端 `operationGateway` 只可作为交互事件补充，不能替代服务端访问日志和授权决策。

## 并发与性能

- 生产环境部署 `npm run build` 生成的静态资源到 Nginx、IIS 或 CDN，不使用 Vite 开发/预览服务器承载多人访问。
- 编辑状态和渲染负载位于各自浏览器实例；服务端主要压力来自图纸 API、鉴权、实时数据网关和持久化。
- 客户端继续使用节点与线稿视口裁剪、逐帧指针合并、按 `dataKey` 精确刷新和受限历史快照。
- 实时数据按工作空间批量发送，每帧最多提交一次客户端响应式更新；不要为每个组件建立独立连接。

上线验收至少覆盖：

| 场景 | 验收点 |
| --- | --- |
| 两个工作空间使用相同文件名和 `dataKey` | 服务端目录命名空间、打开、保存、撤销、剪贴板和运行时值互不串用 |
| 同一图纸两个标签页从相同修订保存 | 后保存的旧修订被阻止，不静默覆盖 |
| 10 个独立浏览器上下文持续 10 分钟 | 无串数据、未捕获异常、持续内存增长或保存失败 |
| 每客户端 2,000 节点压力图纸 | DOM 规模由视口决定，连续拖动和滚动无明显冻结 |
| 高频实时数据 | 只有对应 `dataKey` 的可见组件更新，同一帧同一键只采用最后值 |

并发测试应记录客户端数量、每客户端图纸规模、消息频率、目标设备、接口 p95/p99、错误率、主线程长任务和内存变化，不能只记录服务器在线人数。
